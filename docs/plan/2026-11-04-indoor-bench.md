# 실내 기체 시험 절차(프로펠러 제거, 2026-11-04 작성)

11-03 현장에서 가정이 틀린 것(RC 셔터, 줌 명령, 망원 파일, 홈 위치)은 **현장에 가기 전에 실내에서 확인**한다(사용자 요구).
이 문서는 조종기를 충전하고 기체를 켠 날 그대로 따라 하는 순서다. 결과는 `docs/evidence/<날짜>-bench/README.md`에 적는다(캡처는 git 제외).

## 0. 준비

- **프로펠러를 모두 뺀다.** 실내에서 시동(CSC)은 시뮬레이터가 켜졌을 때만 한다.
- 조종기는 정식 충전기로 80% 이상 충전한다(PC USB로는 충전이 모자라 11-04에 0%가 됨). 기체 배터리도 80% 이상.
- SD 카드 사진 수를 적어 둔다(새로 생긴 파일만 대조하려고).
- PC: `adb devices`로 RC가 보이는지 확인한다. 최신 main을 `./gradlew.bat installDebug`로 설치한다.
- 로그: RC `Android/data/kr.co.dl_dji/files/logs/ops-YYYYMMDD.jsonl`. 단계마다 시작 시각을 적고, 끝나면 이렇게 받는다.
  - `MSYS_NO_PATHCONV=1 adb pull /sdcard/Android/data/kr.co.dl_dji/files/logs/ D:/kiie/tmp_bench/`
- 화면은 RC 화면 녹화(녹화 + 기능 버튼 조합)로 남긴다. 키를 누른 순간과 로그 시각을 맞추려는 것이다.

## 1. 땅에서, 시뮬레이터 없이 (기체 켬, 모터 정지)

| # | 할 일 | 기대 | 확인(로그·파일) |
|---|---|---|---|

| 1.10 | **5D** 상하좌우·누름(목록, 계획, 판독 화면에서 각각) | 선택 이동·확인 | `rcKey` 5D, 화면 변화 |
| 1.11 | 비행 모드 스위치 N → S → F | 상단 바 모드 표시가 바뀜 | `rcSwitch flightMode` |

| 1.13 | 계획 화면 열기(새 미션) | **홈이 자동으로** 기체 위치(GPS 잡히면)나 조종기 위치 | `plan homeAuto`·`homeUpgrade`의 `source` |
| 1.14 | 기체를 손으로 90°씩 돌림 | 지도의 파란 화살표와 나침반이 같이 돎 | 상단 기수 숫자, 캡처 |
| 1.15 | 짐벌 다이얼(왼쪽) | 짐벌 각 표시가 따라옴 | 내비 원판 짐벌 막대 |

- 1.12 실내는 GPS가 없어 비전 센서만 동작할 수 있다. 값이 안 나오면 밝은 곳에서 다시 하고, 그래도 없으면 "실내 불가"로 적는다.
- 1.13 실내에서 GPS가 안 잡히면 조종기(안드로이드) 위치가 나와야 한다. 둘 다 없으면 "위치 없음" 안내가 나와야 한다.

## 2. 시뮬레이터 미션 (대평선 근처 36.48010, 127.33090)

시뮬레이터는 홈 왼쪽 위 표지(`KEPCO 점검`)를 길게 눌러 연동 검증 화면을 열고 [시뮬레이터 켜기]로 켠다. 시험 미션은 대평선 프로젝트에서 **전주 3개**(그중 1개는 설비 전주 R6처럼 설치기기 있는 것)로 만든다.

| # | 할 일 | 기대 | 확인 |
|---|---|---|---|
| 2.1 | 계획 → 저장 → 비행 전 점검 화면 | Pilot 2 순서, 홈·배터리·RC·SD, 표준 HMS | 캡처, `preflight next` |
| 2.2 | 체크리스트 → [비행 임무 업로드] | 업로드 뒤 버튼이 [시작] 하나로 바뀜 | `mission` 업로드 응답 시간 |
| 2.3 | [시작] | 이륙 → 첫 전주 | `mission photoActions`(렌즈별 동작 수), `camera captureLenses` |
| 2.4 | 지점마다 사진 | **지점당 동작 수만큼 파일**(광각 `_W`, 망원 `_Z`, 설비 지점은 더 많음) | `media download`의 `name`·`lens`, `photo` 로그의 `viewpoint`·`pole` |
| 2.5 | 비행 중 썸네일 | 촬영 뒤 1~3초 안에 미니맵 위 썸네일, 설비 상자 | 촬영 시각과 썸네일 표시 시각 차이(`detect` 로그) |
| 2.6 | FPV | 실시간 탐지가 도는 동안 영상이 끊기지 않음 | 화면 녹화로 확인 |
| 2.7 | RC **일시정지** 버튼 | 제동·호버, 미션 칸 ▶ | `rcKey`, 미션 상태 |
| 2.8 | 일시정지 중 화면 셔터·줌 | 동작함, 사진은 가까운 전주 `MANUAL`(20m 안) | `manual shoot`, `photo` 로그 |
| 2.9 | 미션 칸 ▶ (또는 5D 누름) | 재개, 중단 지점부터 이어 감 | `flight` 재개 로그 |
| 2.10 | 미션 중 화면 줌 버튼 | **막힘**(의도, 10.5) | 버튼 흐림 |
| 2.11 | RTH 길게 1초 | 삐 소리, 상단 바 "RTH 진행 중", 지도에 H까지 녹색 선 | `rcKey` RTH, 비행 상태 |
| 2.12 | 착륙 → 확인 | 소티 완료 화면, 정밀 탐지 시작 | `precise gate`(pause null), `precise photo` |
| 2.13 | 판독·앨범 | 사진이 전주·방향·렌즈별로 맞게 붙음 | 파일 이름과 화면 대조 |

**렌즈별 촬영 동작 형식**(5.6, `WpmlWriter.photoActions`): 2.4에서 망원 파일이 나오지 않으면 같은 미션을 아래 순서로 다시 올려 어느 형식에서 `_Z`가 생기는지 확인한다. 결과로 5.6의 "동작 형식은 실내 시험으로 확정" 문장을 고친다.
- ① 동작마다 `payloadLensIndex` 하나(`wide` → `zoom`, `useGlobalPayloadLensIndex` 0) — 지금 기본
- ② ①과 같고, 망원 동작 앞에 줌 배율 동작(`zoom`, 초점거리)을 넣음
- ③ 카메라 "사진 저장"을 렌즈 하나로 두고 앱이 미션 전에 렌즈를 바꿈(동작은 렌즈 없이 `takePhoto`)

## 4. 끝나고

- **시뮬레이터를 끄고** 기체를 끈다(시뮬레이터 상태로 다음 실비행을 하지 않게).
- 로그·SD 파일 목록·화면 녹화를 PC로 옮기고 `docs/evidence/<날짜>-bench/README.md`에 단계별 결과를 쓴다.
- 확인한 항목은 `docs/design/11-pilot2-parity.md` 상태를 "실기 확인"으로 바꾼다.
- 실내에서 못 본 것만 현장 재시험 목록으로 남긴다: 지형 추적, 실제 GPS 홈, 바람, 먼 거리 다운로드 시간, 망원 사진의 탐지 정확도.
