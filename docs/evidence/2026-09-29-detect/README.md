# AI 탐지 연결 증빙 (2026-09-29)

범용 탐지 모델(COCO로 학습한 yolo11n, TFLite float16)을 앱 폴더에 넣고 모의 기체로 전주 5개를 점검했습니다.
앱이 저장한 탐지 결과를 같은 모델을 PC(TensorFlow)에서 돌린 기준값과 대조했습니다.

## 다시 돌리기

```bash
bash tools/export_coco_model.sh                     # build/models/coco-yolo11n-fp16 생성(처음 한 번, 약 3분)
./gradlew installDebug
bash docs/evidence/2026-09-29-detect/smoke.sh       # 약 4분, 에뮬레이터 Pixel_8
```

## 시험 조건

- 모델 폴더 2개를 넣었습니다.
  - `coco-yolo11n-fp16`: 정상 모델입니다. 경고 라벨은 시험용으로 `person`만 지정했습니다.
  - `zz-broken`: 라벨을 10개만 넣어 규격을 어긴 모델입니다. 이름순으로 가장 뒤라 앱이 먼저 검사합니다. 앱은 이 모델을 거부하고 정상 모델을 써야 합니다.
- 모의 기체는 사진 4장을 이름순으로 돌려 가며 씁니다.
  - `1-bus.jpg`: 버스와 사람
  - `2-zidane.jpg`: 사람과 넥타이
  - `3-pole.jpg`, `4-pole.jpg`: 사람이 없는 전주 그림
  - 전주마다 2장(광각, 망원)을 찍으므로 1·3·5번째 전주는 사람이 있고, 2·4번째 전주는 사람이 없습니다.
- `bus.jpg`와 `zidane.jpg`는 Ultralytics 패키지에 들어 있는 예제 사진입니다. 저장소에는 스크린샷으로만 남깁니다.

## 결과 (`verify.txt`)

대조 항목 16개가 모두 일치했습니다.

- 규격에 맞지 않는 모델을 거부했습니다. 로그: `출력 텐서 [1, 84, 8400] ≠ [1, 14, N] (라벨 10개)`. 앱은 `coco-yolo11n-fp16`을 썼습니다.
- 점수 0.45 이상인 탐지 21개가 앱과 PC 양쪽에 모두 있었습니다.
  - 상자 IoU는 최소 0.972였습니다.
  - 점수 차이는 최대 0.014였습니다.
  - 차이는 리사이즈 방식(Android Canvas와 PIL)에서 옵니다.
- `person`만 `alert`로 저장했습니다. 결과 화면의 이상 전주는 1, 3, 5번째로, 기준값과 같았습니다.
- 알림음은 이상음 3회, 점검 완료음 2회였고 오류음은 없었습니다.
- 추론 시간 로그가 사진마다 1줄씩, 모두 10줄 남았습니다.
  - 에뮬레이터 추론 시간은 중앙값 약 110ms였습니다.
  - 전처리는 약 120ms 걸렸습니다.
  - RC Pro 측정은 PoC ⑤에서 합니다.

## 이번 작업에서 고친 것

- 처음에는 `model.json`에 상자가 0~1 비율이라고 적었습니다. onnx2tf로 변환한 모델은 픽셀 단위로 내보내기 때문에 앱의 탐지가 195개로 불어났습니다.
  - `"boxes": "pixel"`로 고쳤습니다.
  - `tools/yolo_ref.py`가 실제 출력 값으로 상자 단위를 판별하고, `model.json`과 다르면 실패하게 했습니다.
- 결과 화면의 탐지 상자가 4:3이 아닌 사진에서 어긋났습니다. 상자를 실제로 사진이 그려진 영역에 맞췄습니다.
