## 알게 된 것

- **11n은 11l보다 확실히 덜 맞는다.** 같은 입력에서 재현율이 1280 전체 0.85 → 0.60, 640 크롭 0.88 → 0.71이다.
  - SUS(현수 애자)는 크롭에서 11개 모두 찾는다. 차이는 거의 **COS**(컷아웃 스위치)에서 난다(11l 4~6개, 11n 1~2개).
  - 학습 결과(test COS 재현율 0.41 → 0.23)와 같은 방향이다.
- 11n은 11l에 없는 상자를 더 낸다(1280 전체 23개 대 19개, `.pt`는 32개). 특히 LP를 5~7개 내지만 11l의 LP 2개와는 하나도 맞지 않는다.
  - 기준이 정답 라벨이 아니라 11l 결과다. 그래서 11n의 "틀린" 상자 중 일부는 11l이 놓친 실제 설비일 수 있다. 라벨을 단 사진으로 다시 재야 확실하다.
- 11n `.pt`와 tflite 1280은 재현율이 같다(0.60). 정밀도 차이는 `.pt`의 직사각형 레터박스와 앱 방식(정사각형 1280, 회색 114) 차이로 보인다.
- 640 전체 사진은 11l과 마찬가지로 쓸 수 없다(0.10). 비행 중에도 **가운데 50% 크롭**이 필요하다.
- 표본이 작다(기준 상자 20개). 수치는 방향을 정하는 근거로만 쓴다.

## 권고

- **정확도로는 11l을 계속 쓴다.** RC에서 11l도 이미 목표 시간 안이다(11-04: 비행 중 640 크롭 286 ms, 착륙 뒤 1280 1.06초/장).
- 11n을 쓴다면
  - 비행 중(live): **640 + 가운데 50% 크롭**(재현율 0.71). RC 시간이 넉넉하면 960 + 크롭(0.76)도 후보다.
  - 착륙 뒤(full): **1280 전체**(0.60). 960 이하는 정밀 탐지로 쓰지 않는다.
- 11n이 이득인 곳은 속도·크기다. 앱 크기 1/10, GPU 첫 열기(11l SUSTAINED 640 60초·1280 429초)도 짧을 것으로 본다.
  - RC 시간은 아직 재지 않았다. 같은 구조의 개발용 COCO 11n 640이 GPU 추론 43 ms였다(11-04).
  - RC 측정(`--es bench all`)에서 11l과 차이가 크고 FPV 실시간 표시(9.6 2단계)에 그 속도가 꼭 필요할 때만 11n live를 검토한다.

## 결론(11-06)

- 사진 탐지(비행 중 최근 1장·착륙 뒤 정밀)는 **11l 유지**: 이미 시간 목표 안이고 11n은 재현율이 크게 낮다(0.88 → 0.71, 0.85 → 0.60).
- 11n의 쓸모는 **FPV 영상 위 실시간 표시(9.6 2단계)**: 640 + 크롭 106 ms라 초당 최대 9장, 11l은 3장.
