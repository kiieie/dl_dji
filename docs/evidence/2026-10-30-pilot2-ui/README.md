## 2. 계획 검증

- 장갑 조작(10.1): 글자만 줄이고 누름 영역은 48dp 이상을 유지한다(비행 중 주요 버튼 56dp 이상).
- MVVM(Android 개발 규칙): [Ⅱ 수동 비행]은 기존 `Command.Pause`(실행기 `requestPause`, 화면 보조 버튼으로 이미 설계)를 `FlightViewModel.pause()`로 보낸다. 화면에 로직을 두지 않는다.
- 안전: 자동 비행 중 화면 버튼은 [RTH 길게]와 [Ⅱ 수동 비행]뿐이다. 일시정지는 정지·호버라 잘못 눌러도 위험하지 않다(Pilot 2 55쪽도 같은 자리에 일시정지가 있다).
- 판독 제거 범위: 탐지는 계속 돌려 결과를 쌓는다. 사용자 결정으로 비행 중 검출 알림음과 전주마다 대기는 두지 않는다(일시정지·C1 계속은 그대로). 판독은 미션 뒤 결과 화면에서만 한다.
- 데이터 주권: 화면만 바꾸고 외부 전송은 없다.

## 4. 리뷰(독립 에이전트 2회)와 수정

1차 6건:
1. [저장]·[▶]을 두 번 누르면 미션이 두 번 저장되고 비행 화면이 다시 열림 → `saving` 표시로 막음.
2. 도구만 바꿔도(이륙 → 취소) 저장 상태가 풀려 같은 경로가 또 저장됨 → 다시 계산 조건에서 도구를 뺌.
3. 편집 직후 "전주가 없습니다"가 깜박임 → 기다리는 동안 "계산 중".
4. 수동 비행 중 경로 알약으로 넘어가면 RTH가 사라짐 → 비행 중에는 알약을 숨기고, 비행 화면 RTH는 기체가 떠 있으면 표시.
5. 키보드가 메모 칸을 가림 → `setDecorFitsSystemWindows(false)` 제거(바 숨김은 그대로 확인).
6. 일시정지 때 주황 칩에 "정상" → "일시정지"·"복귀 중".

2차 3건:
1. 4번의 RTH가 실행기 대기 상태에서는 아무 일도 하지 않음 → `FlightViewModel.returnHome()`이 기체에 바로 RTH.
2. 이어 계획에서 이전 미션 상태 기록이 실패하면 `saving`이 남음 → 같은 `runCatching` 안으로.
3. 도구를 고른 뒤에도 대기 중 계산이 한 번 돎 → 해가 없고, 막으면 취소 뒤 경로가 비는 문제가 생겨 고치지 않음.
