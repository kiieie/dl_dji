# 2026-11-04 설비 탐지 모델(facility_v1_coco) 변환·정확도 확인

사용자가 학습한 모델은 YOLO11l, imgsz 1280, 4종(COS·LP·SUS·LA)이다. 원본 가중치는 `models_src/`(git 제외)에 있다.

변환은 두 단계로 했다.
- ONNX: 기존 `D:/kiie/projects/inspection/.venv`의 Ultralytics 8.4.50을 썼다.
- tflite: `build/yolo-export/venv`의 tensorflow 2.19 + onnx2tf 1.20으로 fp16을 만들었다(`tools/export_facility_model.py`).
- 결과는 `build/models/facility-v1-coco-{640,960,1280}-fp16/`(각 약 50MB)이다.

## 정확도: 원본(.pt, 1280)과 일치율

- 사진: 11-03 대평선 #19·#20 실제 사진 80장(광각, 27m, 전주에서 10m 사선)
- 도구: `tools/compare_facility_models.py`
- 일치 기준: 같은 클래스이고 IoU 0.5 이상

| 모델 | 입력 | 재현율 | 정밀도 | PC 시간/장 |
|---|---|---|---|---|
| tflite 1280 | 전체 사진 | 0.85 | 0.89 | 803 ms |
| tflite 960 | 전체 사진 | 0.60 | 0.71 | 433 ms |
| tflite 640 | 전체 사진 | 0.05 | 0.33 | 206 ms |
| tflite 960 | 가운데 50% 크롭 | 0.71 | — | 528 ms |
| tflite 640 | 가운데 50% 크롭 | **0.88** | — | 299 ms |
| tflite 640 | 가운데 70% 크롭 | 0.61 | — | 315 ms |

- 크롭 행의 재현율은 크롭 안에 있는 기준 상자(20개 중 17개)에 대한 값이다.
- 가운데 50%를 640으로 돌리면 픽셀 밀도가 전체 1280과 같다. 그래서 **비행 중 실시간 표시는 640 모델 + 가운데 50% 크롭**으로 한다. 사진은 전주를 겨냥하므로 설비는 대부분 가운데에 있다.
- 착륙 뒤 정밀 탐지는 1280 전체 사진으로 한다.
- 표본이 작다(80장에서 기준 상자 20개). 수치는 방향을 정하는 근거로만 쓰고, 다음 현장 사진으로 다시 잰다.

## 알게 된 것
- **원본 모델도 이 사진에서는 거의 못 찾는다**(80장에 상자 20개, conf 0.25).
  - 학습 사진(DPS-137L)보다 우리 광각 사진에서 설비가 훨씬 작게 찍힌다(27m, 사선 10m).
  - **망원(7배) 사진**이 이 모델에 맞는다. 망원 촬영 동작(5.6, 2026-11-04 구현)이 들어가면 망원 사진으로 다시 잰다.
- 1280 tflite가 원본과 다른 2건은 LP 2개다. fp16 변환이나 레터박스 차이로 보이며, 표본이 작아 판단을 미룬다.
- 조종기(RC Pro) 시간은 앱 안 측정 기능으로 잰다. 외부 측정 도구는 실행 허가가 없어 쓰지 않았다.
