## 1. 개요

### 1.1 목적

배전선로 전주(DL pole)의 GPS 좌표 목록(CSV/Excel)을 불러와 지도에 표시하고, 사용자가 지도에서 지정한 영역 안의 전주를 **배터리 소모가 가장 적은 순서**로 자동 비행하며 촬영·분석하는 점검 앱을 만든다.

### 1.2 핵심 시나리오

1. 운용자가 사무실에서 전주 좌표 파일을 가져오고, 현장 지역의 지도를 미리 내려받는다.
2. 현장(오프라인)에서 지도 위에 사각형이나 다각형을 그려 점검 영역을 정한다.
3. 앱이 영역 안의 전주를 골라 최적 경로를 만들고, 배터리 한 개로 부족하면 여러 번의 비행(소티)으로 나눈다.
4. 운용자는 고도, 속도, 짐벌 각도 같은 비행 파라미터를 정하고 비행을 시작한다.
5. 드론이 전주에 도착하면 **촬영 → 이미지 다운로드 → YOLO 분석 → 알림음 → 5초 대기** 후 다음 전주로 이동한다.
6. 운용자는 언제든 RC Pro의 **하드웨어 일시정지 버튼**을 눌러 자동 비행을 멈추고 직접 조종할 수 있다. **하드웨어 버튼**(C1/C2 매핑 또는 일시정지 버튼 재누름, PoC ⑥에서 확정)으로 재개하면 **다음 미점검 전주**로 자동 비행을 이어 간다. 하드웨어 재개가 불가능할 때를 위해 화면의 큰 [재개] 버튼을 보조로 둔다.
7. 비행이 끝나면 점검 결과(사진, 탐지 결과, 위치)를 확인하고 파일로 내보낸다.

### 1.3 설계 원칙

- **오프라인 우선**: 현장에서는 인터넷 없이 모든 기능이 동작해야 한다.
- **데이터 주권**: 비행, 영상, 위치 데이터가 **중국을 포함한 외부 서버로 나가지 않아야 한다.** 중국계 지도나 SDK는 사용하지 않는다(7장).
- **안전 우선**: 자동 비행은 항상 운용자가 개입할 수 있어야 하고, 배터리와 통신 상실에 보수적으로 대응한다.
- **교체 가능성**: 기체(DJI), 지도, 탐지 모델은 인터페이스 뒤에 두어 교체하거나 모의 객체로 바꿀 수 있게 한다.

## 2. 요구사항

### 2.1 기능 요구사항

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| F-01 | CSV 파일에서 전주 데이터(전주번호, 위도, 경도 WGS84)를 가져온다. UTF-8과 CP949(EUC-KR)를 모두 지원한다. | 필수 |
| F-02 | Excel(.xlsx) 파일에서 가져온다. | 2차 |
| F-03 | 가져오기 검증: 좌표 범위(대한민국), 중복 전주번호, 누락 값 오류 보고 | 필수 |
| F-04 | 오프라인 지도(VWorld 위성·일반 지도)를 영역 단위로 내려받고 관리한다. | 필수 |
| F-05 | 지도에 전주를 표시하고, 사각형이나 다각형으로 점검 영역을 그린다. | 필수 |
| F-06 | 영역 안의 전주를 자동 선택하고, 전주를 개별로 포함하거나 제외한다. | 필수 |
| F-07 | 이륙 지점 기준으로 배터리 소모를 최소화하는 방문 순서를 계산한다. | 필수 |
| F-08 | 배터리 예산을 넘으면 경로를 여러 소티로 자동 분할하고, 소티별 예상 시간과 배터리를 보여 준다. | 필수 |
| F-09 | 비행 파라미터를 설정한다: 이동 고도, 점검 고도, 속도, 수평 오프셋, 짐벌 각도, 렌즈(광각/망원/열화상), 대기 시간(기본 5초), 배터리 예비율 | 필수 |
| F-10 | 자동 비행으로 전주를 순차 방문하고, 도착 시 촬영, 다운로드, 분석, 알림, 대기를 수행한다. | 필수 |
| F-11 | 일시정지/재개: **일시정지와 재개 모두 RC의 하드웨어 버튼이 1차 수단**(화면 버튼은 보조)이다. 일시정지 시 수동 조종으로 전환하고, 재개 시 다음 미점검 전주로 이동한다. | 필수 |
| F-12 | 수동 촬영: 일시정지 중 운용자가 기체를 움직여 원하는 각도(측면 사선 포함)로 촬영하고 해당 전주에 연결한다. 자동 촬영은 수직 하향만 한다. | 필수 |
| F-13 | 주기 분석: 일시정지나 호버 중 라이브 영상 프레임을 일정 간격으로 분석한다. | 2차 |
| F-14 | 음성/알림음: 도착, 촬영 완료, 이상 탐지, 배터리 경고, 일시정지/재개 | 필수 |
| F-15 | 전주별 점검 상태(미점검/완료/건너뜀/실패)를 저장하고, 중단 후 이어서 점검한다. | 필수 |
| F-16 | 결과 조회(사진 + 탐지 박스)와 내보내기(CSV + 이미지 + JSON, ZIP) | 필수 |
| F-17 | 비행 후 원본 사진을 일괄 다운로드하고 정밀 재분석한다. | 2차 |
| F-18 | 탐지 모델 파일(.tflite + 라벨)을 교체한다(외부 저장소에서 가져오기). | 필수 |

| ID | 요구사항 |

| N-02 | 외부 전송 금지: 앱이 수집한 데이터는 사용자가 내보내기 전까지 기기 밖으로 나가지 않는다. |

| N-08 | 일시정지와 재개는 RC 하드웨어 버튼으로 가능해야 하고, 일시정지는 앱이 응답하지 않아도 동작해야 한다. 자동 비행 화면에는 조작 가능한 버튼을 최소화한다(일시정지 상태에서만 부가 버튼 표시). |

### 2.3 범위 제외 (1차)

- 실시간 영상 위 탐지 박스 오버레이
- 지형(DEM) 기반 고도 자동 보정 (13장 로드맵)
- 가시권 밖(BVLOS) 비행
- 서버 연동, 다중 기체 동시 운용
- 탐지 모델 학습 (앱 밖에서 수행하고, 앱은 모델 규격만 정의)

### 2.4 1차 MVP 범위

**포함**: CSV 가져오기(고정 헤더 자동 인식), 오프라인 지도와 다각형 영역 지정, 전주 선택과 편집, 경로 계획과 소티 분할(고정 파라미터 + 핵심 4개 설정), 자동 비행 루프(도착→촬영→다운로드→분석→알림→대기), 하드웨어 일시정지와 재개, 수동 촬영·건너뛰기, 앱 재시작 복구, 결과 목록과 내보내기, 전체 이미지 1회 추론 탐지.

**MVP 이후**: 프리셋, 소티 중간 재계획, 에너지 모델 자동 보정, 원본 일괄 다운로드와 재분석, 컬럼 매핑 화면, 타일 분할 추론, 주기 분석(F-13), Excel(F-02), DEM 보정, Matrice 4E/4T.

## 14. 확정이 필요한 사항 (검토 요청)

**확정됨**

- 가시권(VLOS) 전용, 법정 최대 고도 150m, 결함 판독 정밀도 요구 없음(탐지 결과는 참고용)
- 전주 주변 환경 정보가 없으므로 기체 장애물 회피 필수, 전선은 이동 고도로 회피
- 일시정지는 RC 하드웨어 버튼, 재개도 하드웨어 버튼 우선(방식은 PoC ⑥에서 확정), 화면 버튼은 보조
- 자동 촬영은 전주 바로 위 수직 하향(광각 + 망원). 측면 사선 등은 **일시정지 중 운용자가 수동 촬영**
- 구간 미션(방식 B)을 기본으로 하고 PoC로 최종 확정, 재개 규칙(6.4), 미리보기 다운로드 기본, 가시권 반경 500m, 배터리 예비율 30%
- DJI LDM 라이선스 파일 보유(오프라인 등록 동작은 PoC ④에서 검증)
- 1차 MVP 범위(2.4), 3개 모듈 시작(3.3), 수동 DI(3.4): 승인됨
- 개발 장비: M3E 기체 없음 → 기체 확보 전까지 `FakeDroneGateway`로 2~3단계를 진행하고, 기체 확보 후 PoC(1단계)를 수행

**미정 또는 확인 대기**

1. **LDM**: 라이선스 파일 전체의 완결성 확인(구현 단계에서 assets에 배치하며 확인)
2. **VWorld 타일 오프라인 저장 약관**: 사용자가 확인 예정. 제한이 있으면 국토지리정보원 정사영상 변환으로 대체(7.4)
3. **결과 내보내기 형식**: 미정. 1차 기본은 CSV + 이미지 + JSON을 ZIP으로 내보내기(F-16), 사내 시스템 형식이 정해지면 추가
