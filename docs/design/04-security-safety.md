## 7. 데이터 보안 및 오프라인 설계

### 7.1 원칙

- 앱이 수집한 데이터(사진, 좌표, 비행 기록)는 **기기 안에만** 저장하고, 사용자가 직접 내보낼 때만 기기 밖으로 나간다(USB, SD).
- **중국계 서비스와 SDK는 사용하지 않는다**: AMap(고덕), Baidu, Tencent 지도, 중국계 분석·푸시 SDK를 쓰지 않는다. Google Firebase 같은 외부 분석·크래시 수집 SDK도 넣지 않는다.
- 지도는 **VWorld(국토교통부)** 타일과 **MapLibre(오픈소스)** 로 구성한다.

### 7.2 DJI SDK 네트워크 차단 (LDM: Local Data Mode)

- MSDK V5의 `LDMManager`로 **로컬 데이터 모드**를 켜서 SDK의 인터넷 접근을 차단한다.
- MSDK 5.5부터는 `SDKManager.init()` **이후에** `enableLDM`을 호출해야 한다(그 전에 호출하면 크래시).
- **앱 등록 문제**: MSDK는 앱 키 등록을 위해 최초 1회 DJI 서버 접속이 필요하다. 인터넷 없이 등록하려면 DJI에서 **LDM 오프라인 라이선스(인증서)** 를 발급받아야 한다.
  - ⚠️ **미검증**: 라이선스가 앱 키 등록(`SDKManager.init()`이 자동 수행)까지 오프라인으로 만들어 주는지, 라이선스 로드 이전에 서버로 나가는 트래픽이 없는지 확인되지 않았다. PoC ④에서 네트워크 캡처로 실측한다.
  - 선택지 ①: DJI에 오프라인 라이선스 신청 → 완전 오프라인 등록 (라이선스 파일 `license_kr.co.dl_dji.txt`(앱 `kr.co.dl_dji` 기준)를 2026-10-28에 확보해 `secrets/`에 두었다(git 제외). **오프라인 등록 동작은 PoC ④ 확인 후 확정**)
  - 선택지 ②: 최초 1회만 인터넷에 연결해 등록하고(앱 키 인증 트래픽만 발생) 이후 LDM + 오프라인 운용
- **라이선스 적용 순서**: `SDKManager.init()` → `LDMManager.loadLocalLDMLicenseContent(내용)`(라이선스 파일 내용 로드) → `enableLDM` → `isLDMLicenseLoaded()` 확인. 라이선스를 먼저 로드하지 않고 `enableLDM`을 호출하면 SDK가 DJI 서버에 라이선스를 요청하므로 순서를 지킨다. (5.18.0에서 PoC ④로 확인, 2026-10-30)
- **라이선스 파일 관리**: 앱 assets에 넣어 배포하되 저장소에는 올리지 않는다(`.gitignore`의 `secrets/`). 빌드가 `secrets/license_kr.co.dl_dji.txt`의 내용을 `BuildConfig.DJI_LDM_LICENSE`로 넣는다(assets 폴더 전체 복사는 다른 비밀 파일까지 APK에 들어가므로 쓰지 않음, 2026-10-30). 앱 API 키도 `local.properties`로 옮기는 방안을 구현 단계에서 검토한다.
- LDM을 켜면 인터넷이 필요한 SDK 기능(비행제한구역 DB 온라인 갱신, 온라인 잠금 해제, 로그 업로드 등)을 쓸 수 없다. 비행제한구역 잠금 해제가 필요한 지역은 사전 절차가 필요하다.
- 조종기(RC Pro) 자체도 시스템 설정에서 LDM을 켜고, 현장에서는 Wi-Fi를 끈 채로 운용하도록 운용 지침에 넣는다.

### 7.3 앱 권한

- `INTERNET`: 지도 타일 사전 다운로드와 DJI 등록에만 사용한다. 설정에서 "오프라인 모드"를 켜면 앱 내 모든 네트워크 호출을 차단한다(지도 다운로드 화면 제외).
- 저장소: 앱 전용 디렉터리와 SAF(파일 가져오기/내보내기)만 사용하고, 불필요한 권한은 요청하지 않는다.

### 7.4 오프라인 지도

- 사무실(인터넷 환경)에서 영역과 줌 레벨(예: 12–19)을 선택해 VWorld 위성·일반 지도 타일을 **MBTiles**로 내려받는다.
- 용량 예시: 5km × 5km, 줌 19까지 위성 타일 기준 수백 MB → 다운로드 전에 예상 용량을 표시한다.
- VWorld 이용약관에 타일 저장 제한 내용은 없다(2026-10-31 사용자 확인). 운영키 신청 때 다시 확인한다.
- **개발 단계 임시 결정(2026-10-29, 사용자. 10-28의 Google 위성 결정을 대체)**: 배경 지도는 우선 **Cesium ion의 위성영상(Bing Maps Aerial, 자산 2)을 온라인으로** 본다. 지도 엔진은 MapLibre(평면) 그대로 두고 배경 래스터 레이어만 더한다(3D 엔진 CesiumJS 교체는 하지 않음). 앱이 ion `GET /v1/assets/2/endpoint`로 Bing 키를 받고, Bing 메타데이터로 `{quadkey}` 타일 주소를 만들어 MapLibre 원본으로 쓴다. MBTiles가 있으면 그 위에 겹쳐 그린다. ion 토큰은 `secrets/cesium.properties`의 `CESIUM_ION_TOKEN`(git 제외)이며 없으면 온라인 배경 없이 동작한다. 인터넷이 없는 현장에서는 마지막으로 받은 타일 주소를 써서 **전에 본 곳만 MapLibre 캐시로 보인다**(캐시 1GB, 2026-10-30. 사무실에서 현장 지역을 미리 둘러보면 된다). 지도를 볼 때 위치(타일 좌표)가 Cesium·Microsoft로 전송되어 7.1 원칙의 예외가 된다.
- **배포에도 같은 위성 배경을 쓴다(2026-10-31 사용자 결정)**: 인터넷이 되면 받아 캐시하고, 안 되면 캐시를 쓴다. 이미 받은 타일은 다시 받지 않는다 — 처음 받은 Bing 타일 주소를 저장해 계속 쓰므로(캐시 열쇠가 바뀌지 않음) 캐시에 있으면 네트워크 없이 보이고, 기한이 지나도 내용이 같으면 조건부 요청(304)만 간다. 현장은 인터넷이 없으므로 **계획을 저장할 때 미션 영역(영역 + 약 300m)의 위성 타일을 z13~19로 미리 받는다**(앱이 직접 받아 `maps/satellite-cache.mbtiles`에 넣고 다른 MBTiles처럼 겹쳐 그림, 이미 있는 타일은 건너뜀, 2만 장 넘으면 최대 확대를 낮춤, 끊기면 지도를 열 때 이어 받음. MapLibre 오프라인 영역은 `file://` 스타일을 못 읽어 쓰지 않음). 토큰은 배포 APK에도 넣는다. 전송되는 것은 7.4 위와 같다(토큰, IP, 본 영역·미션 영역의 타일 좌표)이고 비행·사진·전주 데이터는 보내지 않는다.
- **배경 지도 선택(2026-10-31 사용자 결정)**: ⑥ 설정에서 **Bing 위성 / VWorld 위성 / VWorld 일반** 중 고른다(기본 Bing, 다음에 지도 화면을 열 때 적용). VWorld는 WMTS `https://api.vworld.kr/req/wmts/1.0.0/{키}/{Satellite|Hybrid|Base}/{z}/{y}/{x}.{jpeg|png}`(z19까지 확인), 키는 `secrets/vworld.properties`의 `VWORLD_API_KEY`(개발키, 서비스 유형 "기타", 2027-04-30까지, 없으면 VWorld를 고를 수 없음). VWorld 위성에는 도로·지명 라벨(Hybrid)을 켜고 끈다. 미리 받기 캐시는 지도마다 따로 둔다(`satellite-cache`, `vworld-satellite-cache`, `vworld-hybrid-cache`, `vworld-base-cache`.mbtiles); 다른 지도의 캐시는 그리지 않는다. VWorld로 가는 것은 키·IP·타일 좌표(국내 서버)뿐이다. 구현 `data/MapBackground.kt`, `data/SatelliteCache.kt`, `core/route/TileMath.kt`.

## 8. 안전 설계

| 위험 | 대응 |
|------|------|
| 지형 고저차(이륙 지점보다 높은 산지) | 1차: 이동 고도를 보수적으로 설정하고, 계획 화면에 "상대 고도 기준" 경고, 가시권 반경 제한. 2차: 국토지리정보원 DEM(오프라인)으로 구간별 최저 안전 고도 자동 계산 |
| 전선과 수목 충돌 | 전주 바로 위 수직 촬영을 기본으로 하고, 점검 고도 하한 설정, **장애물 회피 필수(꺼져 있으면 시작 차단)**. 센서가 가는 전선을 못 볼 수 있으므로 이동 고도로 위를 넘는 것을 1차 방어로 한다. 전주 주변 환경(전압, 전선 이격)은 미확인이라 현장 답사로 보완 |
| GPS 오차(전주 좌표와 기체 모두) | 점검 고도에 여유를 둠, 전주 좌표 오차 경고. 추후 RTK 모듈 지원 검토 |
| 배터리 부족 | 5.5 실시간 검증, 예비율 하한 20%, 기체 저전압 RTH는 그대로 유지 |
| 앱과 기체 연결 끊김 | `LinkLost` 상태(6.4): 새 명령 중단, 재연결 시 재동기화 후 `Paused` |
| 바람 | 1차는 예비율 30%로 대응. 기체가 보고하는 풍속이 임계값을 넘으면 경고 표시 |
| 통신 상실 | 미션 중: RTH. 구간 사이 호버 중: 기체 페일세이프 동작을 RTH로 설정(비행 전 점검에서 확인) |
| 앱 비정상 종료 | 기체는 현재 미션을 계속하거나 호버함. 앱 재시작 시 `Paused` 상태로 복구 |
| 운용자 개입 필요 | **RC 하드웨어 일시정지 버튼이 1차 수단**(앱 응답과 무관하게 기체가 멈춤). 앱은 이를 감지해 동기화. 앱이 멈추면 즉시 RC 스틱으로 수동 조종(운용 지침) |
| 규정 | **가시권 비행만 지원**, 최대 고도 150m(앱이 입력 검증), 비행 승인 여부는 운용자 체크리스트로 확인(앱이 공역을 자동 판정하지는 않음) |
