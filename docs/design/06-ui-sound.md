## 10. 화면 설계 (가로 1920×1080)

| 화면 | 주요 요소 |
|------|-----------|
| ① 프로젝트 목록 | 프로젝트 카드(전주 수, 점검 진행률), 새 프로젝트, 설정 |
| ② 데이터 가져오기 | 파일 선택(SAF), 인코딩 자동 판별, 헤더 자동 인식(실패 시에만 컬럼 매핑), 미리보기, 오류 목록 |
| ③ 계획(지도) | 전체 화면 지도, 전주 마커(상태별 색상, 묶지 않고 하나하나 점으로 표시, 축소하면 작은 점), 영역 그리기(사각형/다각형), 선택 전주 수, 경로와 소티 색상, 예상 거리·시간·배터리, 핵심 파라미터 4개(이동 고도, 점검 고도, 속도, 배터리 예비율)와 접힌 "고급" 패널, "비행 시작" |
| ④ 비행 | **FPV 영상(메인)** + 상단 핵심 상태(배터리, 예상 복귀 필요량, 고도, GPS) + 현재/다음 전주와 진행률 + 대기 카운트다운. **자동 비행 중 버튼은 [RTH](길게 눌러야 동작)뿐**이며 일시정지와 재개는 **RC 하드웨어 버튼**을 쓴다. 일시정지 상태가 되면 보조용 **큰 [재개]** 버튼과 [촬영] [건너뛰기] [완료 처리] [다시 계획]이 나타난다. 미니맵과 최근 썸네일은 기본으로 접혀 있고 탭하면 펼쳐진다. |
| ①-1 미션 목록 | 프로젝트 안의 미션 카드(상태, 남은 전주, 마지막 비행 날짜, 판독 진행률), [새 계획] [이어하기] [판독] |
| ⑤ 결과·1차 판독 | 전주 목록과 지도, 사진 뷰어(탐지 박스 표시), 필터(검출·미판독·판정별), 판정 패널, 원본 일괄 다운로드, 내보내기 |
| ⑥ 설정 | 오프라인 지도 관리, 모델 관리, 비행 파라미터 기본값과 프리셋, 에너지 모델 보정값, 오프라인 모드, LDM 상태 |

```
자동 비행 중                                      일시정지 상태 (하드웨어 버튼 후)
┌──────────────────────────────────────┐        ┌──────────────────────────────────────┐
│ 🔋78% (복귀 필요 32%) 50m  GPS ●●●●○  │        │ 🔋78% (복귀 필요 32%) 50m  GPS ●●●●○  │
│                                      │        │  ⏸ 일시정지됨 — 수동 조종 가능        │
│              FPV 영상                 │        │              FPV 영상                 │
│                                      │        │                                      │
│ 현재 A-1234 (7/23)  분석 중 → 대기 3s │        │  ┌──────────────┐ [촬영][건너뛰기]   │
│                          [RTH 길게]  │        │  │   ▶ 재  개    │ [완료 처리]        │
│  (미니맵·썸네일: 탭하면 펼침)          │        │  └──────────────┘ [다시 계획][RTH]   │
└──────────────────────────────────────┘        └──────────────────────────────────────┘
      일시정지 = RC Pro 하드웨어 버튼
```


- FPV와 텔레메트리 위젯은 DJI UX SDK(샘플 저장소의 `android-sdk-v5-uxsdk`) 컴포넌트를 재사용한다. Compose에서는 `AndroidView`로 감싼다.
- 화면의 **[재개]** 버튼은 하드웨어 재개가 불가능할 때를 위한 보조 수단이며, 화면에서 가장 크고 초록색이다. 장갑을 낀 손가락으로 쉽게 누를 수 있도록 화면 하단 중앙에 두고, 일시정지 상태에서만 표시한다. 자동 비행 중에는 잘못 누를 수 있는 버튼을 두지 않는다.
- ③ 계획 화면의 전주 개별 포함/제외(F-06): 영역 안 전주를 누르면 전주 카드에 [제외] 또는 [포함] 버튼이 나온다. 제외한 전주는 지도에 회색으로 표시하고 경로 계산에서 뺀다. 핵심 파라미터 4개는 장갑을 낀 손가락으로 누를 수 있게 [−][+] 버튼(48dp)으로 바꾸고, 6.3 범위를 벗어나면 오류 문구를 보여 주고 경로 계산을 막는다.
- 기체 연동(`DjiDroneGateway`) 전에는 ④ 비행 화면이 `FakeDroneGateway`로 실행된다. 이때 화면에 "모의 기체"를 표시하고, FPV 자리에 전주·기체 위치를 위에서 본 그림을 그린다. RC 하드웨어 버튼 대신 모의 조작 줄([RC 일시정지] [RC 재개] [배터리 −30%])을 둔다. 계획 화면에서 계획을 저장하면 [계획 저장]이 [비행 시작]으로 바뀐다. [다시 계획]은 4단계 뒤에 붙인다.
- ⑤ 결과 화면(1차): 왼쪽은 전주 목록(소티·순서, 상태, 사진 수, 이상 수)과 [전체]/[이상만] 필터, 오른쪽은 고른 전주의 사진과 탐지 박스다. 위쪽에 완료·건너뜀·실패·미점검·검출 개수와 [내보내기]가 있다. 화면 문구는 "이상" 대신 "검출"을 쓴다(9.2). 비행 화면의 "미션 완료"와 프로젝트 카드의 [결과]로 들어간다. 결과 지도와 원본 일괄 다운로드는 기체 연동 뒤(4단계)에 붙인다.
- 내보내기(F-16): `export/<missionId>.zip`을 만든 뒤 SAF로 저장 위치를 고른다. ZIP에는 `result.csv`(전주별 결과, UTF-8 BOM), `mission.json`(미션·소티·파라미터·사진·탐지), `images/`(받은 사진)가 들어간다.
- 모의 기체는 전주번호 대신 렌즈·좌표를 그린 JPEG을 돌려주고, 모의 탐지기(`FakeDetector`, 모델 버전 `fake-1`)는 사진 5장마다 1장에 "모의 이상" 박스를 낸다. 결과 화면과 이상 필터를 기체·모델 없이 확인하려는 것이다. 앱 폴더에 모델(9.1)이 있으면 TFLite 탐지기를 쓴다. 사진에는 경고 라벨(`alertLabels`) 상자를 빨간색, 그 밖의 탐지 상자를 노란색으로 그리고, 이상 개수와 [이상만] 필터는 경고 라벨만 센다.
### 10.1 시각 규칙 (2026-09-29)

- **Material Design 3를 엄격히 따른다.** 버튼, 칩, 카드, 대화상자, 상단 바는 Material3 컴포넌트를 쓰고, 색과 글꼴은 `MaterialTheme`의 역할(`colorScheme`, `typography`)로만 지정한다. 화면 코드에 색 값을 직접 쓰지 않는다. 예외는 사진 위 탐지 상자, 지도 레이어처럼 데이터를 그리는 색뿐이다.
- **톤앤매너는 DJI 조종 앱(DJI Pilot 2) 방식을 따른다.** 어두운 바탕에 흰 글자, 파랑 강조색을 쓰고, 영상·지도 위의 정보는 반투명 어두운 패널에 올린다. 초록은 정상·완료, 주황·노랑은 주의, 빨강은 위험·RTH에 쓴다. DJI 로고, 아이콘, 상표는 쓰지 않는다.
- 테마는 다크 하나만 쓰고 동적 색(Material You)은 끈다(`ui/theme/Theme.kt`). MD3에 없는 의미 색(성공, 주의)은 확장 색으로 테마에 둔다.
- 장갑을 낀 손가락으로 누르므로 터치 영역은 MD3 최소 48dp보다 크게 둔다. 비행 중 주요 버튼은 56dp 이상이다.
- **디자인 시스템 동기화**: claude.ai 디자인 시스템 프로젝트를 `/design-sync`로 연결하면 그 토큰과 컴포넌트를 기준으로 한다. 연결 전에는 `ui/theme/`의 값이 기준이다.

- **화면 흐름**: 가져오기 → 영역 지정 → 요약과 비행 전 점검(체크 결과를 한 화면에) → 비행 → 결과 순서의 마법사 형태로 안내한다.
- **2인 운용 흐름(F-19, F-20)**: 비행 화면은 조종사용이라 판독 요소를 두지 않는다. 소티가 끝나면 "소티 완료" 화면이 배터리 교체 안내와 이번 소티의 검출 전주 수를 보여 주고, 보조자가 [1차 판독]으로 들어간다. 오른쪽 판정 패널에 큰 판정 버튼 3개(검출 맞음 / 검출 없음 / 재촬영), 대상 칩(조류 둥지, 이물질), 메모가 있다. AI가 놓친 대상은 칩으로 직접 추가한다. 앱은 이상 유무를 판정하지 않는다(9.2). 2차 판독은 내보낸 ZIP으로 다른 플랫폼에서 한다.
- **이어하기(F-20)**: 미션 카드의 [이어하기]는 남은 전주로 비행 전 점검을 연다. 마지막 비행 날짜가 오늘과 다르면 대화상자로 [이어서 비행] / [남은 전주로 새 계획] / [취소]를 묻는다. 이륙 지점이 계획과 멀면 다시 계획한다(5.4).
- 와이어프레임: 증빙 페이지와 같은 방식의 Artifact(2026-09-29)로 공유한다.

## 11. 알림음 설계

| 이벤트 | 소리 |
|--------|------|
| 전주 도착 | 짧은 비프 + "도착" |
| 촬영·분석 완료(정상) | "점검 완료" |
| 대상 검출(조류 둥지, 이물질) | 경고음 2회 + "검출" |
| 일시정지 / 재개 | "일시정지" / "재개, 다음 전주로 이동" |
| 배터리 경고 / RTH 권고 | 반복 경고음 + "배터리 부족, 복귀 권고" |
| 오류(업로드 실패 등) | 오류음 |

- 사전 녹음한 음성 파일(ogg)을 `SoundPool`로 재생한다. 오프라인 환경이라 TTS에 의존하지 않는다.
- 음성 파일을 녹음하기 전까지는 `ToneGenerator` 신호음으로 대신한다. 이벤트마다 다른 음을 쓴다.
- 음량과 음성 켜기/끄기를 설정에서 조절한다. RC Pro 스피커가 작으면 블루투스 이어셋 사용을 권장한다.
